## Fixes shipped

### LINE notification race condition (URGENT bug)
**Symptom:** When a user submitted two requests back-to-back via "Submit Another Request", only the second one's LINE Flex message arrived in the maintenance group. The first one's `sendLineAfterUpload` never fired. Jane hit it twice on 24 Apr; reproduced by Jay on 25 Apr.

**Root cause:** Client-side `google.script.run` callback chain was fragile. Two layered problems:
1. `resetApp()` was wiping the globals (`attachedFiles`, `submissionData`) that the in-flight upload chain relied on. → Fixed first by snapshotting state into closure-locals in `onSubmitSuccess` and the event-support submit handler.
2. That fix wasn't enough. Starting a new `google.script.run.submitRequest()` while an earlier `uploadSingleFile` success-handler is still pending **drops the older callback** (undocumented but empirically reliable). The terminal `sendLineAfterUpload` call was never made for the first submission.

**Final fix (the one that holds):** Moved the LINE trigger server-side. `uploadSingleFile` now accepts a `triggerLine: { folderId, submission }` payload on the last file; after the upload (success or failure), the server itself calls `sendLineAfterUpload` internally. Client no longer owns the completion path.

**Files:** `Drive.js` (uploadSingleFile, 2 try/catch trigger blocks), `WebApp.html` (uploadFilesBackground + uploadEventFilesBackground — removed terminal client-side LINE call, added isLast flag).

**Why it kept "failing" during testing:** `clasp push --force` had been failing silently for hours due to expired OAuth (see Tooling → SessionStart hook). My edits sat on disk but never reached Apps Script. Once Jay reauthed and pushed, the fix went live.

**Status:** Code deployed. Still owed: one clean dual-submit test from Jay on the post-reauth deploy to confirm it actually works in production.

### Removed dead code: `unsendLineMessage`
`Line.js` had an `unsendLineMessage(messageId)` function targeting `https://api.line.me/v2/bot/message/{id}/cancel`. That endpoint **does not exist** in the LINE Messaging API. LINE has no bot-side delete for group messages; the "Unsend" feature in the LINE app is client-side UI, personal chats only, 24h window, never exposed to bots. Plus no code was ever capturing `messageId` from push responses, so even if the endpoint existed there'd be nothing to pass.

**Status:** `unsendLineMessage` and `unsendTestMessage` removed from `Line.js`.

## Tooling

### MCP server registration
Jay's general-purpose Google Sheets + Drive MCP server (at `LA PATIS - MCP/server.py`, despite the name) was registered for Claude Desktop but not Claude Code. Created `.mcp.json` in `FC_FM` root pointing at his Python 3.13 interpreter + `server.py`. 13 tools now available: `list_spreadsheets`, `get_sheet_metadata`, `read_range`, `read_full_sheet`, `read_multiple_ranges`, `search_in_sheet`, `get_named_ranges`, `write_range`, `append_rows`, `create_spreadsheet`, `get_file_info`, `list_folders`, `search_files`. Used immediately to pull real venue codes, technicians, contractors, REQUESTS rows, and OT tracker fields for the dispatch app mock data.

### SessionStart hook — clasp auth health check
Added a `SessionStart` hook to `.claude/settings.json` that runs `clasp deployments` silently at the start of each new Claude Code session. If clasp can't reach Apps Script (expired OAuth / `invalid_grant` / `invalid_rapt` / network / etc.), injects a prominent warning into the session context: "Run `clasp.cmd login` in a PowerShell terminal before any code changes."

**Why this exists:** the PostToolUse hook running `clasp push --force` on every file edit was failing silently for the entire first half of this session due to an expired OAuth token. Multiple "fixes" appeared to be deployed but never actually reached Apps Script. Cost ~2+ hours of misdiagnosis. The SessionStart hook closes this loop for future sessions. (Note: it can't catch mid-session auth expirations — the auto-push hook would still fail silently then.)

Also saved a feedback memory entry: `feedback_clasp_auth.md` — "If a deployed fix behaves like old code, check clasp auth before re-diagnosing."

### Stop hook removed
The Stop hook prompting Claude to update CLAUDE.md's Current Status section was firing relentlessly and re-arguing the same point. Removed from `.claude/settings.json` per Jay's request. PostToolUse auto-push hook unchanged.

### PowerShell vs bash gotcha
`clasp login` in PowerShell hit `cannot be loaded because running scripts is disabled` (default execution policy blocks `.ps1` wrappers). Workaround: use `clasp.cmd login`, or switch the VS Code default terminal profile to Git Bash.
